# SPA authenticates via session cookies + CSRF, not bearer tokens

The React SPA at `frontend/` talks to the Django Ninja API at `backend/` using Django's session cookie plus a CSRF token echoed in `X-CSRFToken` — not a bearer token in `Authorization`. This follows from [ADR 0001](./0001-django-auth-with-custom-user-model.md): since identity lives in Django-owned tables, sessions are the native transport, and a token scheme would re-introduce exactly the verification-middleware layer ADR 0001 rejects. Sessions also give us real server-side revocation (delete the row, the cookie is dead) which bearer tokens cannot without a denylist. The accepted cost is that the SPA must (a) be configured for CORS-with-credentials (`CORS_ALLOW_CREDENTIALS = True`, `credentials: 'include'` on every fetch) and (b) echo the `csrftoken` cookie as an `X-CSRFToken` header on every mutating request; the cookie is seeded by `@ensure_csrf_cookie` on `GET /api/auth/me`, which the SPA already calls on cold load.
